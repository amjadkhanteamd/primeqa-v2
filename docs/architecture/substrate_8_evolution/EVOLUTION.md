## 2026-05-31 — Substrate opened; grounding-validity predicate + recipe-grounding leg (D-112 / D-113 / D-114-flagged)

Substrate 8 opened — the **evolution layer**: it governs whether a test remains *meaningfully true* as the org evolves. Faculty-first (mirroring how S6 opened): the semantic core opens; the evolution *mechanics* (manifests, triggers, reverse-index, re-grounding orchestration) are explicitly fenced (SPEC §6 / `DEFERRED_ITEMS.md`). SPEC + D-112 committed on `phase-5-substrate-4-crud` (PR #5, merged).

**The keystone (D-112).** Identity is org-independent *by construction* — `identity_hash` strips `version_seq` + `external_id` (the C0/C1 canonicalization invariants), so a rename / formula-edit / re-sync **cannot** change a claim's identity. Therefore org evolution is **never** an identity-axis event — **always** a grounding-axis event. S8 governs grounding continuity *under identity preservation*; it never changes what a test means (the S2 constitution already mandates identity-preserving-versions-only). One sentence: **S8 re-asks generation's grounding questions against the current org.**

The semantic core is a deterministic **grounding-validity predicate** `(artifact, current org) → intact / drifted / broken` — pure, on-demand, stateless, **two-level** (claim-grounding + recipe-grounding, which drift independently). Its legs are *generation's grounding checks, re-asked*: claim-grounding → S1 entity-resolution; recipe-grounding → S3 derivation; admissibility → S3 admissibility logic (an extensible set; a field-value-validity leg is hinted). **Dependency law:** `S8 → {S1 resolution, S3 derive, S3 admissibility}`, **parallel to S6, never S6 → S8** — the decisive reason is *epistemic* (S6 judges post-run with the actual run evidence; S8 judges pre-run by derivation; the stronger-evidence faculty must not route through the weaker). Plus the **supersession law**: re-grounding is an *identity-preserving supersession* — a new version with the **same** `identity_hash`, on the existing lineage spine, stamped `recipe_s8_rewrite` / `grounding_evolution`. Meaning is the invariant; grounding evolves.

**Slice 1 — the recipe-grounding leg (D-113).** `recipe_grounding_validity(payload, subject, *, s1) → intact / drifted / broken` (`primeqa/evolution/recipe_grounding.py`) — does a behavioral-negative recipe's stored payload still violate the current VR formula? Built on a **new neutral `formula.evaluate` primitive** (`primeqa/semantic/formula/eval.py`, Kleene three-valued) — *not* S3's `derive` (D-112's "S3 derive" line was approximate: the leg *evaluates* `formula + payload → fires?`; `derive` *solves* `formula → a violating assignment`). **Object-level** (the recipe pins no VR — only a generic `FIELD_CUSTOM_VALIDATION_EXCEPTION`): **intact** = ≥1 active VR's current formula evaluates `True`; **drifted** = none triggered but ≥1 active evaluable VR exists; **broken** (reason-tagged `no_active_vr` / `formula_non_evaluable`). Produce-only, no production caller (purely dormant). D-113 refined SPEC §2/§3; the `intact`-masks-drift limitation (an unrelated required-field VR firing) is the deferred VR-pin.
