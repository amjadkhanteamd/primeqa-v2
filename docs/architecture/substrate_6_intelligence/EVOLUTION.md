## 2026-05-27 — Substrate opened; deterministic-attribution foundation (D-111 / D-111.1)

Substrate 6 opened — the interpretation layer: it takes S4's captured truth (a grounded run outcome + evidence) and produces a structured, QA-readable **interpretation** (what was tested, what happened, the semantic attribution). The boundary is sharp and locked (D-111): **S4 captures truth and owns the outcome; S6 consumes `evidence.outcome` and explains it, never re-judging it.** Deterministic-first: the interpreter attributes from the evidence; LLMs (later) phrase + cluster only, never invent the attribution. Package `primeqa/interpretation/` (distinct from v1's `primeqa/intelligence/`). SPEC + D-111 committed.

**Slice 1 — the deterministic interpreter (D-111).** `interpret_run(RunEvidence) → Interpretation` — pure, no LLM, dispatching on vertical (behavioral negative vs inspection) + outcome to a semantic `verdict` (`prohibition_enforced` / `prohibition_not_enforced` / `rejected_unasserted_reason` / `asserted_metadata_present`/`…_absent` / `not_evaluated`), an evidence-derived `attribution`, and `evidence_refs` into the real `RunEvidence`. The outcome is **carried verbatim** (a constructed-inconsistent run is restated, never flipped). Produce-only.

**Slice 2 — deeper attribution (D-111.1).** `attribute_run(interpretation, evidence, *, s1) → Interpretation` enriches the two *failed* behavioral verdicts with a structured `Cause` (one of five `cause_kind`s), pass-through for the rest, never re-judging the outcome.
  - **2a (offline):** the `Cause` model + the `S1VrReader` port + the classification logic — `prohibition_not_enforced` → `vr_inactive` / `vr_formula_drift` (re-derive via the D-107 parser) / `enforcement_gap`; `rejected_unasserted_reason` → `other_vr_fired` (match the rejection message to S1's per-VR `error_message`) / `platform_constraint`. Stub-driven.
  - **2b (S1-backed):** the production `S1ValidationRuleReader` reads a subject Object's VRs **through S1's query interface** (`SemanticOrgModel`) — the inter-substrate read-through pattern (S6-3), no raw S6-local SQL. It composes `get_entities` + `get_related(APPLIES_TO, inbound)` + the new **`SemanticOrgModel.get_entity_details`** (a general, S1-owned detail-table read — the consumer-driven increment D-022 anticipates — added because `is_active` lives on `validation_rule_details`, not in `attributes`). Live-proven against real S1 (seeded), end-to-end through `attribute_run`.

The deterministic-attribution foundation is complete: a run's evidence → a structured, evidence-cited interpretation with a deeper cause for the failure modes that matter. On `phase-5-substrate-4-crud` (PR #5).

## 2026-06-01 — LLM phrasing (presentation layer, invent-nothing) (D-117)

The second phase-7 S6 layer: **LLM phrasing** — the other held `DEFERRED_ITEMS` §2 item (S6-Q-006). A presentation layer over the deterministic interpretation: turn the structured `{outcome, verdict, attribution, cause}` into QA-readable `{headline, explanation}` prose — **inventing nothing** (only those deterministic facts reach the model, so it restates them but can never source a new one; the deterministic core stays the attribution's sole author). Mirrors **story_view** — the canonical "LLM over a structured artifact" v1 pattern (migration 048): a thin enricher over `gateway.llm_call` + a Haiku prompt module + a nullable JSONB column + a per-tenant flag + best-effort caps.

**The boundary split — the LLM stays out of `interpretation/`.** The LLM lives in **v1**: `intelligence/interpretation_phrasing.py` (`InterpretationPhrasingEnricher.phrase` via `llm_call(task="interpretation_phrasing_generation")`, Haiku, never raises, hard `[200]/[2000]` caps) + the `interpretation_phrasing@v1` prompt module (registered in `registry.py` + a Haiku-only chain in `router.py`). The **schema + a pure-SQL writer live in the substrate**: `result_store.py` gains a nullable `phrasing` column (alembic `20260601_0020`) + `set_phrasing(session, run_id, dict)` — a plain `UPDATE`, no LLM, no commit. So `import primeqa.interpretation.result_store` still pulls in **no `intelligence`** — the LLM-free invariant holds; v1 → substrate is the allowed direction (the consumer annotates the producer's row). The on-demand+cache primitive `get_or_phrase` reads the row's cached `phrasing` (hit → return) or phrases once + caches via `set_phrasing`. Per-tenant gate `llm_enable_interpretation_phrasing` (migration 050, default off) — the caller checks it, mirroring the story_view caller.

**S6-Q-006 resolved:** runs **on-demand + cached** on the row, stored as a **column on `s6_interpretations`**, and invention is prevented **structurally** (the prompt receives only the deterministic facts — no evidence, no org model — so there is nothing new to invent from). **Honest caveats:** S6 stays **write-only** — `get_or_phrase` is built + tested but **not live-fired** (no consumer reads interpretations yet — the dormant-substrate posture); the LLM call is **best-effort** (failure → `None`, caches nothing, the caller falls back to the deterministic attribution) and **stub-tested** in CI (the real Haiku output is verified periodically, as story_view's is, not CI-gated). Verified: phrasing unit 7 + integration 4 green; full `test_representation` 304. On `phase-7-substrate-6-interpretation`.

## 2026-06-03 — Full-surface verdicts + the in-substrate consumer (D-136 / D-137)

**Phase 5 (program) — two slices.** The interpreter is brought current with the **realized S4 execution surface** (Phase-3 closed: inspection existence/property + the data-recipe negative **and positive**), and the write-only store gains a read/consumer surface.

**Slice 1 — full-surface verdicts (D-136).** Fixed a real mis-interpretation + closed a precision gap. `interpret_run` dispatched on step *shape* — *any* `CreateAttemptEvidence` → the negative-prohibition branch — so the **positive value-claim** (D-115: create-expect-success → read-back → assert, which *also* emits a `CreateAttemptEvidence`) was verdicted `prohibition_enforced` ("the violating create was rejected") — nonsense. The robust discriminator: the negative emits a *single* `(create,)` step; the positive emits create + read + assert. So **create + `AssertEvidence` → `_interpret_positive`** (`value_persisted` passed / `value_not_persisted` failed / `not_evaluated` errored); **create alone → `_interpret_behavioral`** (unchanged). And `_interpret_inspection` now dispatches on `AssertEvidence.predicate`: `exists` → present/absent (existence + metadata-relationship — unchanged); `equals`/`is_null` → `asserted_value_matches` / `asserted_value_differs` (property — the field *is* present, only its value differs). `Verdict` grows by four; attribution stays evidence-derived. **No migration** (`verdict` is TEXT); the only behavioral change is a positive value-claim's persisted verdict moving from a wrong value to a right one. Verified: 10 pure full-surface tests + 30 interpreter unit + 15 S6 integration green.

The substrate read API stays LLM-free + v1-DB-free; the live-fire + flag-read live in v1 (the allowed v1→substrate direction).
